<contracts>
These decisions close implementation discretion; keep them together in the public types/docs, without creating a general sync framework.

**Public/session boundary.** Export openOfflineQueue({audience,tenantId,actorUserId,getSession}). Audience is a validated absolute HTTP(S) API origin/base ending /api/v1, without credentials/query/hash; HTTP allowed for loopback development. Scope is the immutable tuple [normalized audience, lower-case tenantId, lower-case actorUserId], never just project/employee. getSession returns the CURRENT in-memory {token,tenantId,actorUserId,generation}, or null; generation is a caller-incremented integer on any login/logout/tenant/actor/token transition. Capture and compare all fields before/after async work, before every send and inside every committing transaction; wrong/missing current identity fails closed for get/list/enqueue/flush/retry/cleanup. Opening a handle grants no server authority. Expose enqueueEvent(event,{evidence?}), enqueueEvidence(input), list(), get(id), status(), flush(), retry(id), storageInfo({requestPersistence?}), cleanupAcknowledged(ids), closeSession(), close(). No arbitrary scope argument on methods, arbitrary URL/method jobs, pending deletion/cancellation, payload edit or auto-rebase API.

close() aborts this handle and releases DB resources without deleting work. closeSession() synchronously invalidates/aborts this handle, then commits a scope authEpoch increment and broadcasts invalidation to other tabs; an authEpoch mismatch invalidates other handles before another send/commit. Same actor reauthentication opens a fresh handle against the new epoch. getSession is authoritative even if BroadcastChannel delivery is delayed. Network already accepted by the server cannot be recalled; stale completions cannot advance local state. Reopen/retry reconciles via exact receipt replay. /me must return matching userId AND tenantId before a flush sends commands; tokens stay solely in memory and Authorization headers, credentials:'omit', redirects:'error'. A supplied same-origin script can forge a session provider: this is accidental-session isolation, not an XSS/OS-user security boundary.

**Local commit/stream.** One versioned native IDB database, stores events/evidence/meta, compound scope keys and scope/employee ordering indexes. All public saves and state updates settle on transaction complete, reject on abort/error; handle blocked upgrade/versionchange explicitly and close stale connections. Request strict transaction durability where accepted, fall back only to a normal native transaction when the browser rejects that option, reporting actual capability. No in-memory/localStorage fallback. No network, hashing or unrelated await inside a transaction. Deep-validate strict supported03a shapes without importing server/Node code. Preserve the original valid event JSON values/string on retries; stable-key JSON equality makes same request/same payload idempotent, changed payload or any event/reserve/attach ID collision a local conflict. Reject undefined/non-JSON/non-finite values. Generate missing new IDs only before the first save; never after a failed delivery. Client shift/report IDs, original occurredAt string, previousEventId and expectedVersion are immutable.

Caller supplies the initial observed expectedVersion. In one readwrite transaction across meta/events/evidence, first new local event establishes that employee's tail, subsequent new events require expectedVersion = retained local tail expectedVersion+1; allocate a local monotonic sequence and update tail atomically. Do not contact the server to rewrite versions. Employee stream key omits project; tabs with the same old tail compete and one receives local_stream_conflict. previousEventId must name the latest known local event in the SAME project for that employee if present, or an externally acknowledged same-project dependency explicitly supplied by the caller; cross-project previousEventId is invalid because03a checks project as well. An absent previousEventId on an initial event remains absent. Across projects use employee version ordering, not a manufactured cross-project predecessor. A blocked/retry-waiting lower-version event prevents higher ones from sending; another employee may progress. Keep tail/acknowledged ID tombstones on acknowledged cleanup so cleanup cannot reset versions or strand a pending dependency. No automatic baseline reset; stale external/server changes block for explicit operator investigation and a new accurately seeded workflow.

Bounds, atomically enforced over the whole database to prevent cross-partition growth:1000 retained event records,32 retained evidence records,64MiB retained Blob bytes, and1 byte–8MiB per file. JPEG/PNG/PDF only. Limits include acknowledged data until intentional cleanup; capacity failure preserves existing records and returns capacity_exceeded without exposing other partition counts. Cleanup accepts only current-scope synced records with no pending dependents; retain compact request/hash/ack tombstones and stream tails. Public states are pending, sending (ephemeral), retry_wait, blocked, auth-required and synced; evidence stage is separate. status includes state, stage, request/file/employee/project IDs, dependency, attemptCount, nextAttemptAt and sanitized lastError; never response dumps/tokens.

**Sending/retry.** Use Web Locks exclusive name scoped to audience+tenant+actor for flush; hold it over the awaited network operation, not an IDB transaction. A second flush uses ifAvailable and returns busy. Missing Web Locks permits durable enqueue but flush returns unsupported_lock; no lease fallback. Process employee heads serially, one-event HTTP batches; no persistent in-flight state required (derive sending in memory), so crash releases the lock and the durable prior stage replays. Every state commit checks captured scope/authEpoch/session generation and original command hash. Use a30s AbortController timeout per request. A flush attempts each eligible event or evidence stage at most once; no sleeping/polling loop. Transient network/timeout/408/429/5xx and ambiguous/malformed2xx responses retain payload with attempts/nextAttemptAt using min(60s,1s*2^min(attempt-1,6)); clamp Retry-After to1–60s when valid. Stop auto-eligibility after5 consecutive failures and expose blocked_retry_exhausted; retry(id) only clears retry counters/delay for the identical job.401 becomes auth-required and stops the flush.403/404 and other permanent business4xx become blocked; stale_version/missing_dependency/lifecycle conflicts stay visible, never skipped or mutated. A retryable per-item500 is transient; missing_dependency blocks for investigation rather than futile polling. New session plus explicit retry can retry unchanged authorization-blocked work after rights are restored; retry cannot resolve stale_version by altering expectedVersion.

Execution200 is not success by itself: require exactly one results item with matching requestId and supported outcome. success/duplicate require status201, result matching requestId/employee/project/shift/kind, version expectedVersion+1, occurredAt same instant, valid receivedAt and all boolean reviewFlags; submit_volume also matches taskId/reportId and exact decimal value (server pads to3 fractional digits), provisional:true/acceptedQuantity:null. Validate error item status/code/retryable types, matching requestId, and reject contradictory shapes. Unknown/extra batch items, mismatched identities, invalid JSON or unsupported status cannot acknowledge. Only commit synced after validation; HTTP/JSON copies do not replace the frozen request.

**Evidence.** enqueueEvidence needs project/employee, filename, contentType, Blob, target plus a local dependencyRequestId naming the queued/acknowledged event (submit_volume for final_report). Event target actor must equal bound actor and requestId dependency; report target must equal the dependency's reportId; project/employee must match. This slice accepts attachments to known local/tombstoned acknowledged events/reports, not arbitrary unverified remote targets. enqueueEvent with optional evidence saves both together; standalone evidence references an existing dependency. Hash Blob bytes with native SHA-256 and freeze fileId, reserve requestId/body, attach requestId/body, target and dependency BEFORE the atomic IDB commit; attach ID is distinct from reserve/event IDs. Blob and metadata are stored atomically as structured clones, never base64. Validate size/type/filename and digest from actual bytes; server still validates magic/content.

Durable stages are queued→reserved→uploaded→synced. Fixed routes: POST /projects/{p}/evidence with frozen reservation, PUT /projects/{p}/evidence/{fileId}/content with original Blob and application/octet-stream, POST /projects/{p}/evidence/{fileId}/attachment with frozen attachment body. Only the attachment waits for the dependency acknowledgement; sending all stages after dependency acknowledgement is acceptable. Reservation receipt is an ORIGINAL snapshot and may still say pending on replay after upload; accept pending/ready only with full identity/declaration match, never infer later stage completion from it. PUT requires200, state ready and matching file/project/employee/filename/contentType/sizeBytes/sha256. Reserve/attach require201 (including exact receipt replay); validate reservedBy matches actor for this newly reserved file. Attachment requires state ready, exact target and attachedBy actor, valid server timestamps; wrong target never acknowledges. Check returned metadata against frozen scope/declaration at every stage; API does not echo tenantId, so enforce it through current /me, fixed path and x-tenant-id. A lost response or failed local stage commit repeats the same stage/IDs, including PUT digest identity. Preserve Blob until attachment acknowledgement transaction completes; retain it until explicit acknowledged cleanup. No automatic orphan cleanup or overwrite.
