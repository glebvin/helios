## Required behavior

1. Store events and actual binary files in IndexedDB with promises resolving only on transaction complete, not request success. Fail local save visibly on abort/quota/unsupported/storage errors; never report success or fall back to ephemeral memory/localStorage. Request strict durability where supported; document browser limits and explicit persist()/estimate() results. No claim of protection against cleared storage/eviction/power loss.
2. Scope every list/get/write/flush by fixed API audience(origin/base), tenantId and actor userId. Tokens live in memory only; never persisted in queue or logs. Session changes/logout stop further sends; another actor cannot flush/read through the public API as that actor. Local storage is not cryptographic protection from same-origin scripts/OS users. Reauthentication must use same actor/tenant; current server identity (`/api/v1/me`) checked before delivery and current token/generation checked between stages. Do not allow arbitrary queued URLs/methods.
3. Managed03a event shapes and durable identities remain exact: requestId is event ID, employee stream expectedVersion across projects, previousEventId chain, client shift/report IDs and occurredAt retained. Across tabs enqueue atomically; same request/same payload is idempotent, different payload conflicts. Use safe per-employee ordering for queued work; serial sending one event at a time is acceptable. Never auto-increment/rebase an already frozen stale-version payload, manufacture server success, silently skip failed predecessor or delete pending/conflicted events. A stale_version/authorization/lifecycle business failure becomes actionable blocked/auth-required state. HTTP200 contains per-item success/duplicate/error; validate request identity/status and response shape before marking synced. Malformed/ambiguous response retains original payload for exact retry.
4. Network failures, lost response after server commit, retriable500/429 etc retain exact request IDs/payload, bounded retry/backoff and manual retry. Busy polling/background hidden work is unnecessary; explicit flush in open app and online signal/manual invocation are enough. `navigator.onLine` is not proof of reachability. Cross-tab flush exclusivity and closing/crashing a tab must not lose a job or allow stale completion to clear another actor's queue; Web Locks allowed with explicit unsupported behavior instead of an untested unsafe fallback. No network await inside IDB transaction.
5. Evidence is an actual Blob, up to8MiB JPEG/PNG/PDF, hash derived from bytes and metadata frozen before local commit. Store related metadata+Blob atomically, not base64. Upload pipeline uses existing reserve(raw metadata requestId) → rawPUT(fileId+digest identity) → attach(separate requestId). All stage IDs and exact bodies persisted; restart after each boundary safely resumes/replays, keeps Blob until server attachment acknowledged. Target exact event actor/request or final-report ID; event dependency must be acknowledged before attachment. Verify server scope/file digest/state/target responses, not just2xx. Failures never drop file; retry/cancel semantics cannot orphan or overwrite user work silently. Preserve max8MiB and add modest explicit count/aggregate byte bounds without new infrastructure.
6. Expose sufficient stable API for UI: enqueue/list/status/flush/retry/close or session switch, pending/error details and storage capability info; allow intentional cleanup of acknowledged data only with clear conditions. Destructive operations on pending jobs are not needed for this slice. Event+photo relationship is preserved even across reload. Do not expand to arbitrary offline approval/quality/material/ID commands or background GPS.
