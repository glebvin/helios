# Внешний наблюдатель готовности

Это отдельная часть R47. Процесс не входит в API и worker: он сам запрашивает `GET /api/ready` и записывает событие только в сухой журнал. Приложение он не перезапускает. Сообщения людям, cron и системная служба этой версией не подключаются. Измеренная доступность 99,5% здесь не заявляется.

## Запуск

```sh
python3 deploy/readiness/observe.py \
  --url http://127.0.0.1:4327/api/ready \
  --interval 30 \
  --timeout 2 \
  --threshold 3 \
  --state /path/to/private/observer-state.json \
  --events /path/to/private/observer-events.jsonl
```

`--interval` — пауза между запросами в секундах. `--timeout` должен быть короче интервала, кроме одноразового `--probes`. `--threshold` — сколько подряд неуспешных ответов нужно до первого сигнала отказа. Повторный запуск читает `--state` и не отправляет тот же сигнал ещё раз.

`--events` — тестовый транспорт: по одной JSON-строке на событие. Тот же объект печатается в stdout. В stderr остаётся только `probe up`, `probe down <причина>` и `signal down` или `signal recovered`. Тело ответа, пароль из адреса и персональные данные туда не пишутся.

Успех — HTTP 200 и JSON с `ok: true` и строковыми `checks` для `db`, `evidence`, `queue`, `worker`, `backup`. HTTP 503 — отказ. Истёкший timeout, недоступный адрес и любой другой ответ, включая 200 без этого JSON, считаются разными причинами отказа. Пока порог не достигнут, события нет. После сигнала отказа следующие такие же ответы его не повторяют. Первый успешный ответ после открытого отказа даёт отдельное событие `recovered`.

Окно 07:00–21:00 Europe/Moscow задано в коде. Отказ, набравший порог вне окна, остаётся в состоянии и становится событием на первой проверке внутри окна, если отказ продолжается. Если до открытия окна готовность вернулась, событие не создаётся: сигнала отказа ещё не было. Восстановление уже открытого сигнала записывается и вне окна.

Состояние хранится в файле с правами `0600`. Повреждённый файл останавливает запуск и не заменяется молча.

## Что остаётся для подключения

Адресат, канал уведомления, расписание на сервере, хранение и ротация журнала, проверка очереди, диска и резервов отдельно от `/api/ready`, а также измерение 99,5% за рабочее окно. Пока эти условия не выбраны, наблюдатель запускается вручную и только с `--events`.
