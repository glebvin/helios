# Учебный S3-адаптер файлов

Это первая часть задачи #105. Адаптер пишет и читает объекты на отдельном S3-совместимом endpoint. Рабочий стенд остаётся на файловом адаптере: `HELIOS_EVIDENCE_STORE` по умолчанию не задан, и тогда создаётся прежний `EvidenceStorage`.

Значение `s3` включает адаптер только вместе с `HELIOS_S3_ENDPOINT`, `HELIOS_S3_BUCKET`, `HELIOS_S3_REGION`, `HELIOS_S3_ACCESS_KEY_ID` и `HELIOS_S3_SECRET_ACCESS_KEY`. Эта версия принимает endpoint лишь как `http://127.0.0.1` и отклоняет порты `54339`, `54441`, `4357`, `54502` и `54512`. Ключи в репозиторий и в журнал проверки не записываются.

Контракт тот же, что у файлового адаптера. Байты принимаются только после проверки размера, SHA-256 и типа. Повтор тех же байтов оставляет один объект. Другое содержимое по тому же ключу не заменяет уже записанное. Ключ объекта — `компания/файл`, оба UUID. Загрузка идёт одним запросом `If-None-Match: *` и с `x-amz-acl: private`. Обрыв запроса не должен оставлять готовый объект. Переменная `HELIOS_S3_INJECT_FAULT=during-put` только для этой проверки обрывает запись после первых байтов; на стенде её не задают.

Проверка `qa/r49-s3.test.ts` поднимает SeaweedFS 4.53 из [seaweedfs-4.53.json](seaweedfs-4.53.json) на `127.0.0.1:54521`. Это отдельный учебный сервер, не имитация успешного HTTP и не хранилище стенда. Каталог `.data/r49` не коммитится.

## Совместимость с R46

Принятый механизм R46 архивирует локальный каталог файлов в `files.tar` и базу в `database.dump`. Объекты учебного S3-бакета в этот архив не входят. Пока стенд читает файловый каталог, первая копия R46 по-прежнему покрывает его байты и связи в базе. После будущего переключения стенда на выбранное хранилище R46 должен копировать уже байты этого хранилища; текущий архив каталога сам по себе таким копированием не станет.

Не входят в эту часть: внешнее место и ключи, регион и размещение, перенос рабочих файлов, расписание, срок хранения, RPO/RTO, публичный или боевой бакет, смена ролей и авторизации.
