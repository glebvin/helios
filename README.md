[Открыть тестовый HELIOS](https://helios-test.evegunina.ru/). Фактический frontend commit указан в `/release.json` и [GitHub Releases](https://github.com/glebvin/helios/releases). Для выпусков людей и заданий API/worker сохраняются на совместимом runtime `1658687e1422`, без миграций и очистки данных. Main может двигаться дальше без автоматической выкладки. Учётные данные передаются приватно.

Основные роли первого прохода: руководитель проекта (`rp` → серверная `director`), прораб (`master`), работник (`worker`), ПТО (`pto`). Остальные девять кабинетов пока ограничены чтением прежней проекции; готовность всех их действий не заявлена.

## Как мы работаем

Одна задача → отдельная ветка → маленькое изменение → автоматические и браузерные проверки → PR с preview → приёмка → объединение в main (обычно squash; для зависимого пакета — сохранение ancestry). Выкладка выбранного коммита выполняется отдельно и не очищает базу.

Принятый внешний вид сохраняется. Подключение API не разрешает заменять экран целиком, менять палитру или выдавать локальный черновик за серверную запись. Владелец оценивает готовый результат; технические проверки и подготовку тестовых данных выполняет агент/разработчик.

## Устройство проекта

- `apps/web` — React/Vite интерфейс.
- `apps/api` — NestJS API, SQL и серверные проверки.
- `apps/worker` — фоновые задания.
- `packages/domain` — общие правила.
- `packages/offline` — устойчивая очередь событий/файлов; восстановленный UI ещё требует подключения.
- `packages/ui` — общие стили и компоненты.
- `deploy/helios-staging` — инструменты тестового размещения, не инструкция запускать reset при каждом релизе.
- `docs` — актуальные руководства и исторические отчёты.

## Документы, которые могут описывать прежнюю реализацию

`docs/ui-api-coverage.md`, `docs/ui-api-status.md` и отчёты пакетов 1–4 описывают более раннюю интеграцию. После восстановления старого frontend они не доказывают готовность текущих экранов. Начинайте с [актуальной карты](docs/ROLE-FLOW-MAP.md); API сверяйте с [OpenAPI](apps/api/openapi.json).

Нет автоматической выкладки из GitHub. CI проверяет код; он не заменяет визуальную приёмку, браузерный сценарий, отдельную проверку offline и физических телефонов.
