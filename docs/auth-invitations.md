# Регистрация HELIOS по приглашению

Руководитель открывает **Люди → Работники → Пригласить работника** или **Люди → Прорабы → Пригласить прораба** и нажимает **Создать ссылку**. Ссылку отправляют одному человеку. В разделе сохраняются действующие приглашения и результат регистрации; список обновляется при возврате к окну и каждые 15 секунд.

Приглашение прораба по-прежнему просит имя, почту и пароль (10–128 символов). Письмо не отправляется. Приглашение работника адресовано одному телефону: человек подтверждает одноразовый код и указывает имя. Почта и пароль для такого входа не создаются. После регистрации открывается кабинет нужной роли. Существующие почтовые аккаунты и их парольный вход сохранены. Самостоятельная регистрация руководителей и ПТО не открывается: в этом модуле приглашения предусмотрены только для работников и прорабов. Расширенная матрица ролей и реестр доступа в этот результат не входят.

## Права и сохранность

- Руководитель приглашает работников и прорабов; прораб — работников своего объекта.
- Код случайный, 12 символов, действует 7 дней и используется один раз. «Обновить код» отключает предыдущую ссылку. Просроченную ссылку можно обновить; использованную — нельзя.
- Код даёт доступ к кабинету, но не заменяет допуск к работе, назначение и проверку документов.
- Пользователь, членство, карточка сотрудника, доступ к объекту, сессия и погашение кода сохраняются одной транзакцией. Ошибка откатывает весь результат.
- Повтор создания/обновления с тем же `requestId` не выдаёт дубликат. Два одновременных получателя одного кода создадут только один аккаунт.
- Уже зарегистрированная почта, включая иной регистр букв, не изменяет существующий аккаунт и не тратит приглашение. Для уже имеющего аккаунт добавление во вторую компанию через приглашение пока не предусмотрено.
- При погашении повторно проверяются текущие права пригласившего. Отозванное членство или доступ прораба к объекту делает его неиспользованные приглашения недействительными.
- Активная сессия другого человека не заменяется незаметно: сначала предлагается выйти.
- Коды доступны только уполномоченным пользователям объекта; в аудит не пишутся пароли, сессии и сами коды. Публичная проверка ссылки показывает роль, название объекта и срок действия.
- Для публичных входа, проверки и погашения предусмотрены ограничение запросов и запрет кеширования ответов. На небольшом стенде лимит общий для экземпляра API: 40 входов и 40 регистраций, 200 проверок приглашений за минуту; возвращается `429` и `Retry-After`.

## API

Контракт: `/api/v1/openapi.json`, 86 операций; прежние пути сохранены. [Независимая приёмка телефона 15 ноября](qa/phone-login-2026-11-15.md).

| Метод | Путь | Доступ |
| --- | --- | --- |
| POST | `/api/v1/invitations` | Руководитель / прораб, с проверкой роли получателя и объекта |
| GET | `/api/v1/projects/:id/invitations` | Руководитель / прораб своего объекта; последние 100 приглашений и зарегистрированные работники / прорабы |
| POST | `/api/v1/invitations/:id/refresh` | Уполномоченный руководитель / прораб |
| GET | `/api/v1/join/:code` | Публичная проверка, не расходует код |
| POST | `/api/v1/join/:code/challenge` | Одноразовый код на телефон приглашения |
| POST | `/api/v1/join/:code` | Публичная регистрация; роль и объект берутся с сервера |
| POST | `/api/v1/auth/phone/challenge` | Код для последующего входа; наличие аккаунта не раскрывается |
| POST | `/api/v1/auth/phone/login` | Существующая сессия по подтверждённому телефону |

При создании передаются `requestId`, `role`, `projectId`, `organizationId`; для работника ещё `phone` и при необходимости `employeeId`. Организация — своя внутри кабинета. При обновлении — новый `requestId`. Регистрация по почте передаёт только `name`, `email`, `password`. Регистрация по телефону передаёт только `name` и шестизначный `code`. Непредусмотренные поля отклоняются. Сервер не принимает от регистрирующегося произвольные роль, кабинет и объект.

## Телефон работника

Телефонный интерфейс включается только явной QA-сборкой `VITE_HELIOS_PHONE_LOGIN=true`. Default сохраняет почтовые приглашения/парольный вход, пока реального провайдера нет. Серверный synthetic-провайдер на публичном стенде автоматически не включается. Последующие реальные SMS, MFA и расширенная матрица — отдельные результаты.


Работник приглашается на конкретный номер. Номер приводится к международному виду: `8` и десять цифр или `7` и десять цифр становятся `+7…`, иначе принимается только `+` и от 8 до 15 цифр. В списках и на странице приглашения видна маска, не полный номер. Роль, компания, объект и работодатель берутся с сервера. Карточка сотрудника связывается, если она передана и ещё не занята другим входом; совпадающий телефон карточки обязателен. Новая карточка создаётся только когда своей ещё нет. Факт ввода телефона сам по себе пользователя, членство и роль не создаёт.

Код — шесть случайных цифр, живёт пять минут, выдерживает пять неверных попыток и запрашивается не чаще одного раза в минуту и пяти раз за десять минут. Тот же `requestId` не отправляет новый код. Новый запрос гасит предыдущий. Код хранится как HMAC с отдельным секретом и привязан к номеру, цели и версии приглашения. Публичный ответ, обычный журнал и аудит код не содержат. Доставка в этой задаче — только синтетический провайдер для проверки: `HELIOS_PHONE_PROVIDER=synthetic` и закрытый каталог `HELIOS_PHONE_QA_DIR`. Без них код не выдаётся. Реальное SMS не отправляется. Универсального кода нет.

Повторный вход: телефон, новый код, существующая сессия на 12 часов и свой кабинет. Неизвестный номер код тратит и сессию не открывает. Чужой кабинет по этой сессии недоступен. Выход отзывает только предъявленную сессию. Отозванное членство приглашение не восстанавливает, другая роль в той же компании не повышается. Если пригласивший потерял право до принятия, ссылка отклоняется.

Миграция `016_phone_login.sql` делает почту и пароль необязательными парой и добавляет подтверждённый телефон и таблицу кодов. Подключение настоящего провайдера, MFA руководителей, смена номера, выбор компании при нескольких членствах, полная матрица приглашений и реестр остаются отдельными результатами.

## Развёртывание

Аддитивная миграция `011_invitations.sql` создаёт приглашения, защищённый RLS список и индекс уникальности почты без учёта регистра. Перед применением проверяются существующие дубликаты адресов и создаётся резервная копия. Повторный запуск мигратора безопасен. Обычный `db:seed` на рабочем стенде не запускается.

Модуль не переводит демонстрационные разделы качества, материалов и ИД на сервер и не подключает офлайн рабочего дня. Их статус по-прежнему указан в баннере стенда.

Для публичного стенда обязательны `HELIOS_QA_URL` и путь `HELIOS_QA_CREDENTIALS` к закрытому файлу с тестовыми входами. Пароли и токены в результаты не выводятся.
