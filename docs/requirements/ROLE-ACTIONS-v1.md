# Матрица ролей и маршрутов пилота

Источник — [ТЗ v1.0 и решения владельца](TZ-v1-baseline.md). Это целевая спецификация, а не таблица уже выданных сервером прав. Первоначальная кодовая база для сравнения — main3e7f230; актуальный каталог и границы включения описаны в [runtime-контрактах ролей](ROLE-CONTRACTS-runtime.md). Реальные команды требуют отдельных PR, текущих scope/version/idempotency checks и отрицательных тестов.

## Роли и разрешённые области

| Бизнес-роль из §5.1 | Действия пилота | Область и запрет |
| --- | --- | --- |
| ГД | Сводки/отчёты всех объектов своей компании, D-01 | Между компаниями нет доступа; подробные персональные данные — отдельное разрешение, роль руководителя не раскрывает медицинские документы |
| ДС | Контроль объектов, сводки, наблюдение «не готово к КС-2» | Явно разрешённые объекты/организация; чтение не даёт право принимать объём |
| ЗДС ССО | Контроль сроков сдачи и замечаний, К | Не выполняет У за ПТО только из-за более высокой должности |
| ЗДС СОСО | У шаблонов сдачи и перечня ИД, контроль реестра | Не подменяет составителя и не переписывает старую версию |
| РП | Ответственный заданий/допусков/сдачи, У дневного задания/допуска; П документов при полномочии | Свой объект, действующее основание для П. Данные табеля — для ДП, не универсальное право изменять сводный табель |
| Мастер СМО | Готовит/отправляет задания, самоконтроль/приёмка мастером, заявки СК и внесение внешнего результата, закрытие дня, корректировки, черновики/сканы | Не подделывает внешнего подписанта; отправка скана не выдаёт П от компании без приказа |
| Бригадир | Начало смены, бригадный факт/фото/простой, чек-лист ОТ | Одна бригада/работодатель по D-06; объём не размножается участникам |
| Рабочий | Своё задание, своя смена, факт, проблема | Нет чужого персонала, утверждения табеля или чужой приёмки |
| ПТО — руководитель ПТО/наш СК | У внутренней приёмки, шаблоны/перечень/реестр ИД; П АОСР по стройконтролю при полномочии | Для скрытых работ/субподрядчиков приёмка обязательна; руководство ПТО и подготовка инженера — разные действия |
| Инженер ПТО | Готовит шаблоны/перечень, реестр, схемы и сканы | Не получает автоматически утверждение своего шаблона |
| ОМТС/кладовщик | Партии, документы о качестве, данные/подготовка входного контроля | Только разрешённый объект/работодатель; неприемлемая партия не доступна в задании |
| СО | Договорные цены единиц и объём к КС-2 | Это цены для готовности, не учёт зарплат/себестоимости |
| ДП/служба персонала | Карточки, сводный табель Р/У, приказ об ответственных лицах | Новая ревизия сводного табеля по D-04; не незаметная правка старой принятой записи |
| ОТиПБ | С допуска, пункты ОТ, контроль фронта/шаблонов | Согласование не подменяет У РП |
| ПЭО/ГБ/ЮО | Просмотр по назначенным правам | Доверенности — этап2; нет автоматической записи в производственные данные |
| Пользователь субподрядчика | Свой персонал, свои задания/предъявления | Проверять работодателя на сервере; одному tenant/project scope недостаточно |
| СК заказчика | В пилоте не входит в систему | Бумажный внешний участник, а не пользователь с выданной ролью customer; guest — этап2 |
| Администратор | Пользователи/роли/справочники/маршруты/сроки/аудит/обмен | Не может изменить подтверждённый объём, табель или подписать за лицо без полномочия |

Существующие13 тестовых кабинетов не покрывают всю эту таблицу. Миграция013 добавляет отдельные коды бригадира, инженера ПТО, СО, пользователя субподрядчика и ПЭО/ГБ/ЮО. Это резерв идентичностей: бизнес-обработчики новых ролей пока закрыты. Точные field permissions и подключение действий выполняются отдельно в R43/R32; нельзя переименовать всем роль в director/pto. Существующие демо-аккаунты не удаляются этим решением; demo customer не считается обязательным guest-сценарием пилота.

## Буквы и переходы

| Буква | Правило | Что сервер обязан отклонить |
| --- | --- | --- |
| Р | Один ответственный за подготовку/срок. Фактический составитель хранится отдельно | Маршрут без Р или с двумя Р |
| С | От0 до3 согласующих, одновременно | Четвёртого С; движение при обязательном неполученном согласовании |
| У | От0 до1 внутреннего утверждающего | Двух У; автоматическое утверждение по таймауту |
| П | Отметка бумажной подписи с действующим полномочием на лицо/объект/тип/срок | Просроченный/отсутствующий/чужой приказ; право только из названия кабинета |
| К | Контроль сроков/эскалация | Выдачу К полномочий С/У/П без самостоятельного основания |
| Д | Однократные данные; после срока явная отметка и продолжение | Превращение отсутствующих данных в выдуманный ответ или обход обязательной проверки материалов/допуска/ИД |

Совмещение Р+У и Р+П в таблице допустимо. Нельзя вводить запрет «всегда разные люди» вопреки указанным комбинациям. Лицо и бизнес-роль не смешиваются: кто фактически выполнил действие, фиксирует аудит.

| Дневное задание | Мастер СМО | РП | — | РП | — | Д: ПТО, ОМТС |
| Готовность фронта | Мастер СМО | РП | — | — | — | Д: ПТО, ОМТС; К: ОТиПБ |
| Допуск работника | Мастер СМО | РП | ОТиПБ | РП | — | Д: ДП |
| Сдача нашему СК | Мастер СМО | РП | — | ПТО | — | К: ЗДС ССО |
| Сдача внешнему СК | Мастер СМО | РП | — | — | РП и внешний СК | К: ПТО |

| Реестр ИД | Инженер ПТО | ПТО | — | — | — | К: ЗДС СОСО |

Внешний бумажный подписант не обязан иметь аккаунт. Для АОСР собственная отметка П и внесённый скан не сливаются. D-02 прямо определяет первую отправку дневного задания: мастер → РП. Привязка новых типов документов делается их отдельными PR; одна эта таблица не создаёт все14 runtime-процессов.

## Минимальные контракты решений

| Действие | Обязательные условия/версия | Аудит и отрицательный пример |
| --- | --- | --- |
| Настроить маршрут | Администратор своего tenant; полная проверка букв/назначений, новая версия | Автор/до/после/дата; admin чужой компании не меняет маршрут, история прежних документов не переписывается |
| Отправить/утвердить задание | Мастер/РП по D-02, свой объект, свежая версия, допуск/фронт/материалы/WorkSequence | Две конкурирующие команды не утверждают разные редакции; рабочему отказано |
| Согласовать допуск | ОТиПБ С, РП У, версия проверки | Мастер не выдаёт за ОТиПБ согласование; истёкший медосмотр блокирует назначение |
| Принять часть объёма | Уполномоченный мастер/ПТО на своей ступени; не больше предъявленного; идентичность принятой части | D-03:17 принятых +1 отклонённый не становятся36; чужой объект/работодатель не доступен |
| Записать внешний результат | Мастер, заявка/попытка/пункты/скан; отдельный внешний подписант | Повтор не создаёт вторую приёмку/ИД; customer без аккаунта не имитируется чужой учёткой |
| Отметить П | Действующие полномочия на объект/тип; скан/подписант и свежая версия | Чужой/истёкший приказ отклоняется, в том числе при поздней доставке |
| Исправить закрытые часы | Мастер готовит первичную корректировку, ДП новую ревизию сводного табеля | D-04: прежние данные/основания сохраняются, повтор не создаёт лишнюю ревизию |
| Принять материал/использовать партию | Маршрут мастер/кладовщик/РП/ПТО/ОМТС, документы и критичные пункты | Отклонённая партия не становится доступной из-за отсутствующего ответа Д |

Технический стиль существующего API сохраняется: повторная проверка актуальных прав на сервере, requestId и expectedVersion, результат после подтверждения, аудит автора/объекта/операции/старого и нового значений. Успех из localStorage, обход guard и изменение чужих записей недопустимы.
