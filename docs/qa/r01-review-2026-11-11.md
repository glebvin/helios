# R01 / PR #28 — проверка контекста кабинета

Исходный PR: ecde7c356606ea5a305bf85ec8ddc013713e4ecc. Проверка и исправления выполнены поверх актуальной main 3244deb. Владелец разрешил последовательную проверку, объединение и выкладку трёх PR; отдельная оценка удобства владельцем не заявляется выполненной.

## Найдено и исправлено

- Девять дополнительных ролей получали пустой список объектов v1, несмотря на разрешённое чтение `/api/desk`. Шапка теперь сохраняет их существующую проекцию доступа, без изменения API и прав.
- Выбор объекта менял подпись, но оставлял задания/смены/отчёты другого объекта. Общая проекция теперь фильтруется по реальному `project_id`; без выбора не подставляется случайный объект.
- Запоздавший ответ desk мог обновить состояние уже другого входа. Ответ применяется только к соответствующей активной сессии.
- На ширине 390 px навигация и минимальные размеры сетки растягивали/обрезали содержимое. Исправлены ограничения ширины и мобильная сетка; настольные палитра и компоновка сохранены.
- Рабочая дата перечитывается при возвращении в окно и раз в минуту. Ошибка запроса очищает неподтверждённую область.

## Проверено

- TypeScript API/web/domain/offline и production Vite build: успешно.
- 7 тестов scope: выбор, пустая/неполная выборка, календарная дата, идентичность входа, связанные записи выбранного объекта, граница дополнительных ролей.
- `qa/roadmap-foundation.mjs`: 16 успешных проверок Chromium на production preview с настоящим API и отдельным PostgreSQL: все 13 кабинетов, два объекта с разными заданиями, 390 px без переполнения/обрезания страницы, истёкшая сессия. Браузерная зона времени Pacific/Honolulu; день приходит с сервера.
- Исходная проблема дополнительной роли подтверждена браузером до исправления; настольные и мобильные снимки после просмотрены.
- Проверены ссылки документов и отсутствие whitespace-ошибок. Frontend-тесты добавлены в CI, чтобы они не оставались только локальными.

QA использовала только отдельную локальную БД порта 54349, API 4357 и preview 5207, синтетические данные. Снимки и машинный отчёт находятся в ignored `.data/pr-review/`; учётные данные не публикуются. Серверная БД не изменялась.

Ограничения: это Chromium и эмуляция ширины, не физический телефон или полный offline/E2E продукта. Старый учебный DayFlow и остальные незавершённые интеграции не принимаются этим шагом. Выпуск и публичный smoke фиксируются отдельно.
