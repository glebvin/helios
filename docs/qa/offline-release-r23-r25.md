## Найденные ошибки и исправления

| Проверка исходного результата | Фактическая ошибка | Исправление |
| --- | --- | --- |
| Первый вход, затем полностью недоступен origin и reload | В кэше только HTML/manifest, пустой экран | Версия оболочки и полный список JS/CSS/шрифтов генерируются при build; установка успешна только после полного кэша |
| «Выйти» при обрыве API | Локальный аккаунт открывался снова | Локальные credentials и снимок закрываются сразу; потеря ответа logout не возвращает аккаунт |
| Фото к существующему отчёту из нового браузера | Требовался submit_volume именно в локальной очереди | Для final_report допустимо отсутствие локальной зависимости; сервер продолжает проверять объект, сотрудника, роль и привязку |
| Начать смену, затем «В работу» | local_dependency_conflict до сети | Команды используют предыдущую локальную команду своего сотрудника/объекта; исходные requestId не меняются |
| Возврат связи после backoff | Не было таймера следующей попытки и обновления фактов | Ограниченный повтор по nextAttemptAt, resume по online/focus, уведомление и повторное чтение фактов |
| Недоступно хранилище снимка | Исключение могло прервать чтение дня | Ошибка кэша объясняется отдельно; живой день продолжает работать, повреждённый снимок отвергается |

Повторное открытие очереди не выполняет logout других вкладок. Пропуск версий после работы другого устройства допускается только при подтверждённой локальной истории; ожидающие команды нельзя перескочить. Подтверждённые Blob освобождаются перед следующей загрузкой с сохранением ключей идемпотентности. Ожидающие файлы не удаляются.

Код исправлений сохранён в `fd56fee06ae537bf2ae644503f5c48f3a7fd14a8`. Позднейшая правка сценария миграции устраняет преждевременное ожидание теста; код приложения после этого не менялся.

## Что проверяется автоматически

В существующем `.github/workflows/checks.yml`: документы, TypeScript, build, frontend unit, domain, API/изоляция, browser smoke и модуль очереди в Chromium/WebKit. Добавлены unit отказа/повреждения снимка и browser regression продолжения после новой серверной версии. Это не автоматический запуск всех локальных UI-сценариев ниже.

Локально подтверждены72 frontend unit,64 механических браузерных сценария очереди и32 сценария настоящего приложения:18 оболочка/файлы/выход,12 события и2 обновление старой версии. TypeScript, production build и ссылки51 карточки прошли. Ошибок JavaScript в итоговых браузерных прогонах нет. Это результаты собственного QA, не заявление о физическом устройстве.

На собственном QA4369/54360 и preview5218:

- `qa/offline-ui-browser.mjs`: полный кэш с первого входа, SHA скачанного фото, реальный отказ IDBObjectStore, потерянный ответ PUT после записи и перезапуск постоянного профиля, две вкладки, полный обрыв origin, давность снимка, выход без сети, отдельный вход мастера,390px.
- `qa/offline-events-browser.mjs`: реальные формы shift_start, segment_change, shift_end и submit_volume; прокси теряет первый ответ после commit, сеть возвращается, повторяет те же bytes/requestId. Чтение API подтверждает одну смену, один рабочий интервал и один непринятый отчёт.
- `qa/offline-update-browser.mjs`: исходная оболочка R25 с ожидающей командой → новая оболочка, тот же requestId и снимок → холодный запуск → одна серверная смена после возврата сети.

Прокси `qa/offline-preview.mjs` разрывает настоящие HTTP-соединения и умеет отключить весь origin. Browser context offline и эмуляция ширины не выдаются за физический телефон. Журнал прокси содержит только синтетические команды, без Authorization и паролей.

## Как повторить локальные сценарии

Нужны зависимости по lockfile, Node24, Python3, совместимый PostgreSQL initdb/pg_ctl и Playwright с установленными Chromium/WebKit. Все порты ниже должны быть свободны. Не менять их на адрес общего стенда. Новые данные создаются в новых компаниях, reset существующих данных отсутствует.

1. `HELIOS_QA_PG_BIN=/absolute/path/to/postgres/bin python3 qa/offline-review-setup.py init` — новая БД54360; конфигурация с новыми случайными реквизитами сохраняется только в игнорируемую `.data/release-r23-r25/qa-config.json` с режимом600. Уже созданный контур не переинициализируется.
2. В отдельном терминале `python3 qa/offline-review-setup.py api` — API4369. Затем `python3 qa/offline-review-setup.py fixtures` — учебные данные и приватные manifest для проверок. Для повторного сквозного прогона создавать новые фикстуры этой командой.
3. Собрать текущую версию: из `apps/web` запустить `node node_modules/vite/bin/vite.js build --configLoader runner --emptyOutDir --outDir ../../.data/release-r23-r25/web`. Для теста обновления нужна также сборка совмещения исходных PR без исправлений, commit12ce4daa989dd0d2a678e60aaf286866e2846827 в `.data/release-r23-r25/before-web`; собирать её в отдельной копии commit12ce4daa989dd0d2a678e60aaf286866e2846827, не переключать рабочую папку исполнителя.
4. `node qa/offline-preview.mjs`. Переменные `PLAYWRIGHT_MODULE` и `CHROMIUM_EXECUTABLE` указывают на установленный runtime. Последовательно запустить `node qa/offline-ui-browser.mjs`, `node qa/offline-events-browser.mjs`, `node qa/offline-update-browser.mjs`. Они управляют одним proxy, параллельный запуск запрещён. Результаты/снимки остаются в `.data/release-r23-r25/`.

`node scripts/check-types.mjs`, `node --experimental-strip-types --test apps/web/src/*.test.ts` и `python3 scripts/check-docs.py` выполняются отдельно. Для библиотеки: `HELIOS_PLAYWRIGHT_MODULE=/absolute/path/to/playwright/index.mjs PLAYWRIGHT_BROWSERS_PATH=/absolute/path/to/browsers node packages/offline/test/browser.test.mjs mechanics`.

## Остаток и границы

Физические iPhone/Android, установка на домашний экран, системное вытеснение хранилища, лимиты конкретных устройств и радиопереключения — R26. Они не проверены эмуляцией. R26 автоматически не начинается; отдельную работу Cursor R27 пакет не затрагивает.

Без сети доступен последний снимок «Моей смены» своего входа. Это не свежие серверные часы и не офлайн всего кабинета. Доставка подготовленной команды не означает локальное подтверждение следующей бизнес-операции: следующий шаг требует подтверждённой версии сервера. Полный рабочий день с произвольной цепочкой новых действий без единого ответа сервера этим выпуском не заявлен.

Модуль ограничивает очередь1000 событиями и32 файлами/64МБ. Ожидание не считается успехом; постоянный отказ/конфликт не повторяется автоматически как новая команда. Вход заново не переносит чужие записи. Полную приёмку пилота сверять с [картой покрытия](../roadmap/PILOT-19.2.md).

## Выпуск и откат

Перед переключением — свежий dump БД, резерв файлов, реальное отдельное восстановление и сверка SHA. После переключения — версия публичного сайта,13 ролей без бизнес-записей, неизменность количества записей в19 таблицах и IDs API/worker/DB. Проверки фиксируются в Release только после их выполнения.

Откат: вернуть gateway/frontend на сохранённый08923d1, сохраняя БД и файлы. Перед откатом оценить клиентский Service Worker: установленный кэш может продолжать показывать новую оболочку до установки предыдущего SW и reload. Не очищать IndexedDB для отката — там могут быть ожидающие команды. Для подтверждённого отката с установленной PWA нужен отдельный smoke обновления клиентской оболочки.
