## Поведение

До R07 в серверной карточке не было интерфейса штатных команд доступа и назначения. Теперь на вкладке «Документы» отдельно показаны привязка аккаунта, членство на выбранном объекте и назначение сотрудника. Палитра, навигация, предыдущие блоки и общая компоновка сохранены.

- GET `/projects/:p`, `/assignments`, `/employees/:e/admission-checks?projectId=:p&limit=1`; director со связанным userId дополнительно читает `/memberships`. Страницы memberships/assignments просматриваются до найденной записи, а не только первые100. Master не вызывает запрещённый memberships API.
- PUT `/projects/:p/memberships/:user` открывает/закрывает доступ существующего аккаунта. Роль определяется сервером, форма не меняет её и не создаёт аккаунт.
- PUT `/projects/:p/assignments/:employee` активирует назначение с id **последней** успешной попытки. Сервер повторно проверяет актуальность шаблона и квалификаций. Нельзя выбрать старую удачную попытку после новой неуспешной. При снятии admissionCheckId отсутствует в теле.
- Worker получает видимость проекта/задач только при активных membership и assignment; master получает доступ через membership. Актуальность допуска не подменяет эти состояния: после изменения квалификации существующее назначение может оставаться активным, но currentAdmission.eligible=false. Это показывается явно, без обещания немедленно скрыть объект от отзыва квалификации.
- Непривязанный сотрудник может быть назначен по серверному контракту, но UI явно говорит, что это не создаёт вход. Не добавлены rawUUID-поля и обход приглашений.
- Каждая команда использует ожидаемую версию и requestId. Полное неподтверждённое тело сохраняется в sessionStorage в рамках компании/пользователя/объекта/сотрудника/операции. После потери ответа и reload повторяется исходное действие, даже если фоновое чтение уже показало изменённое состояние. Это метаданные повтора, не локальный источник бизнес-результата. 409 требует явного чтения; network/5xx сохраняет ту же команду; definitive4xx не выдаётся за успех.
- Ошибка чтения не изображает пустое назначение. Late reads от старого контекста игнорируются. Фокус/интервал60с перечитывают сервер; кнопки записи доступны только director.

Backend, SQL, OpenAPI и зависимости не изменены. Нет миграций или очистки активной базы.

## Доказательства

Изолированный localhost: PG54349, API4357, production preview5207. `qa/create-people-review.mjs` создаёт новый синтетический tenant, не сбрасывая существующие данные. Для владельца и автоматических тестов созданы **разные компании**; пароли только в игнорируемых локальных файлах с mode0600. Ни один секрет не входит в отчёт/снимки.

- TypeScript всех пакетов, production build и проверка документов — успешно. Сохраняется прежнее предупреждение Vite о размере JS bundle; оптимизация bundle вне R07.
- 28 frontend unit tests: прежние25 +3 R07 (отсутствие checkId в revoke, точная версия/чек, восстановление исходной команды, различение отказов).
- `qa/project-access-browser.mjs`: **15** сценариев. Отсутствие доступа worker/master; отдельные состояния; membership без assignment не открывает worker project/tasks; ложный check отвергнут; последнее настоящее подтверждение и атомарное восстановление membership; master read/direct403; failed latest блокирует старый pass; assignment revoke с сохранённым membership; membership revoke с сохранённым assignment; потерянный подтверждённый ответ + reload + тот же полный body без новой версии;409 и explicit reread; read failure/retry; unlinked employee не получает логин; foreign404/worker403;390px.
- На общем кандидате повторены `qa/qualifications-browser.mjs`17, `qa/admission-template-browser.mjs`19 и `qa/admission-check-browser.mjs`17: **всего68** успешных браузерных сценариев, без JS runtime errors. R06 прогон создаёт шаблон R05 и квалификацию R04 через UI, затем проверяет попытки/ошибки/историю.
- Снимки до/после: те же owner fixture, director, светлая тема, объект,1440×1000. Отдельно просмотрены панель и390px. Это Chromium и эмуляция ширины, не физический телефон/Safari.
- CI finalhead фиксируется ссылкой в PR. Из-за feature-base используется существующий workflow_dispatch, workflow не расширен. Независимое инженерное review и оценка владельцем не объявляются выполненными.

Воспроизведение R07: сначала `node --experimental-strip-types qa/create-people-review.mjs` с HELIOS_QA_ADMIN_DATABASE_URL изолированного localhost54349 и HELIOS_PEOPLE_REVIEW_OUTPUT в приватную папку. Затем `node qa/project-access-browser.mjs` с HELIOS_QA_CREDENTIALS на созданный manifest, PLAYWRIGHT_MODULE/CHROMIUM_EXECUTABLE и при необходимости HELIOS_QA_URL/HELIOS_QA_OUTPUT. Создавайте отдельный fixture для нового прогона: тест проверяет исходное отсутствие доступов. Активный сервер для теста не подходит.
