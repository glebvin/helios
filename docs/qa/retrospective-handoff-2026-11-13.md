PR82 содержит новые правила передачи и этот каталог. Публикация документации в main не означает обновление приложения на сервере.

## Как читать доказательства

- Head — последняя вершина исходного PR по GitHub. Merge — коммит включения, а для цепочки — узел интеграции. При squash head не обязан быть предком main: проверен ancestry merge-коммита.
- Проверки общего пакета относятся к указанному кандидату/выпуску; число проверок пакета не приписывается каждому дочернему PR.
- Старые «PR открыт»/«публикация впереди» в сохранённых описаниях относятся ко времени их написания. Датированное дополнение в каждом завершённом PR связывает их с фактическим выпуском.
- Локальные preview/фикстуры/снимки из `.data` — исторические артефакты, доступность этих процессов сейчас не предполагается. Для повторения агент готовит отдельный QA по версии и сценариям; пароль и клиентские данные в PR не помещаются.
- Зелёные unit/API/общий smoke не доказывают выполнение каждого локального браузерного сценария. Качество новой передачи не контролируется наличием одних заголовков.

1. У PR68/R13 и 69/R14 исторический UI smoke — failure, offline — skipped. У PR70/R15 checks финального исторического head не найдены. Это сохранённые факты GitHub, а не новые отказы текущего сервера. В [отчёте смены](release-shifts-2026-11-12.md) описаны исправления гонки перехода/фонового чтения; итоговый кандидат 72/0fe51be и main8aacf8b прошли все 4CI. Исходные head не объявляются отдельно полностью зелёными.
2. Общий CI автоматически запускает frontend unit, API/domain, `qa/ci-smoke.mjs` и тесты offline-библиотеки. Профильные скрипты людей/заданий/смены/табеля/ПТО сейчас прямо в workflow не подключены. Например, `qa/overview-browser.mjs` зависит от локального 5217 и фикстур `.data`; наличие файла не делает 18 сценариев автоматической регрессией.
3. Историческая навигация мастера не содержит отдельного «Мои дела»; R21 показывает ему живую главную. R22 не реализует приёмку качества и подписание акта. Общие формулировки ранних отчётов не расширяют реально проверенное поведение.
4. Ограничение отчёта объёма при нескольких закрытых сменах дня сохраняется. Успешный одиночный сценарий не подтверждает многосменный; граница остаётся в R26/R50.

## Воспроизведение и текущий просмотр

Агент выбирает точный commit и изолированный контур, читает [Development](../DEVELOPMENT.md) и профильный QA-отчёт, готовит синтетические роли/данные и исполняет существующий сценарий. Где подготовка живёт только локально, это пробел воспроизводимости, а не готовая команда для другой машины. Общий стенд не очищается ради проверки.

Владельцу доступны [тест-кейсы по модулям](../test-cases/README.md). Он оценивает готовый preview и удобство; техническое повторение, роли/запреты/ошибки и подготовку фикстур выполняет агент. На публичном стенде допустимы пустые дни — создавать фиктивные смены ради демонстрации не требуется.

Датированные дополнения PR/Issues сохраняют исходные описания. Пароли, токены, приватные manifest и серверные конфигурации в этот каталог не включаются.
