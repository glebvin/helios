## CI и полный roadmap

[PR58](https://github.com/glebvin/helios/pull/58) добавляет карту покрытия исходного ТЗ/19.2 и51 исполнимый шаг в существующем GitHub; автоматические browser smoke и offline Chromium/WebKit выполняются на одноразовых CI базах без рабочих секретов. Проверки документов контролируют ссылки, покрытие источниками и отсутствие циклов зависимостей. Это не означает, что будущие функции реализованы.

Триггер pull_request теперь охватывает все базы, включая цепочки зависимых PR. Обычный процесс больше не требует ручного dispatch для каждого feature-base PR. CI не публикует сайт; конкретный выпуск выполняет ответственный агент по поручению владельца. Итоговые CI и опубликованный commit фиксируются в PR58 и GitHub Releases после прогона.

## Уборка веток и ответственность

Пять старых remote archive-веток заменены проверенными аннотированными тегами с теми же именами и commit SHA. В исходной локальной копии удалены8 старых веток после сохранения их коммитов в GitHub-тегах;6 чистых рабочих папок переключены в detached HEAD без удаления файлов. Грязные/активные папки сохранены. До уборки сделаны и проверены полные Git bundles, staged/unstaged patches и untracked archives; отдельные грязные worktrees также сохранены. Секреты в Git не передавались.

Не удалять новый код R08/R09. Архивные теги и резервные файлы сохраняют возможность восстановить старые прототипы без их смешивания с основной разработкой. Локальные папки с незакоммиченным кодом могут по-прежнему иметь отдельные ветки — это сохранённая работа, не повод выполнить reset.

Рабочая договорённость владельца: Cursor реализует ограниченные задачи и передаёт PR/SHA/проверки; Codex проверяет CI/основания, объединяет согласованный пакет, выпускает и убирает проверенные ветки. Владелец оценивает продуктовый путь и вид. Два агента не редактируют один checkout одновременно.
