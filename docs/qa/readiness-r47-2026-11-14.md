## Результат и найденные дефекты

`/api/health` сохраняет прежнюю проверку живого API. Отдельный `/api/ready` возвращает200/503 и безопасные статусы БД, метаданных очереди, каталога файлов и worker. Это эксплуатационный сигнал, не разрешение принимать пилот/все бизнес-процессы.

В исходнике экспорт `@helios/api/ready` добавлен только в source package. Серверная сборка сохраняла старые экспорты db/jobs, что воспроизведённо даёт ERR_PACKAGE_PATH_NOT_EXPORTED при разрешении импорта worker. Исправлены TypeScript mapping и генератор runtime exports; CI теперь собирает реальный runtime, устанавливает production lockfile и импортирует граф API и экспорты worker.

У исходного readiness не было границы ожидания. Теперь проверки идут параллельно с2с пределом, БД/очередь используют отдельный pool max1 с1с таймаутами подключения/SQL/запроса. Он не занимает business pool. Общая проба одна на процесс и кэшируется5с; повторные запросы не создают лавину запросов и сигналов. В журнале только имена отказавших проверок и восстановление, без исключений/URL/паролей. Ошибки idle connection и pg-boss обрабатываются безопасными сигналами.

Heartbeat запускается после регистрации consumer. Каждая отметка требует успешного чтения БД и нужной очереди со стороны worker; при зависании проверки отметка не обновляется. Цикл не перекрывает свои проверки. Каталог вместо файла, будущая дата и возраст более30с считаются неисправностью. В production отсутствие настройки worker также блокирует readiness. В dev без настройки виден явный not_configured.

В Docker API читает общий runtime-volume только для чтения; worker пишет туда heartbeat. Новый каталог принадлежит node, файл0600. Есть отдельный healthcheck worker. PostgreSQL/evidence volumes и бизнес-схема не меняются. Место под файлы проверяется отдельно от возможности записи: missing/full/unwritable.

UI, frontend-код, SQL, права ролей, пароли и зависимости не меняются. Обновляются API/worker и эксплуатационная конфигурация. Скрипты и результаты с секретами в Git не включаются.

## Эксплуатация и границы

[Краткая инструкция](../operations/readiness.md). Кэш добавляет до5с к обнаружению; heartbeat до30с плюс этот кэш. Heartbeat подтверждает живой зарегистрированный consumer и доступ worker к БД/очереди, но сам по себе не доказывает выполнение конкретной бизнес-задачи. Нет заявлений об измеренном SLA, физических телефонах, постоянных внешних оповещениях или согласованном адресате. Backup:not_configured означает отсутствие подключённого контроля внешних резервов, не отсутствие локального проверенного release backup. R46, полный мониторинг/адресат/хранение журналов и остальные критерии R47 остаются открытыми.

Откат этого выпуска — предыдущий полный runtime9c74a4d и его Compose с теми же БД/evidence, без восстановления БД. Он уже читает v2-хеши паролей. Нельзя откатывать дальше к старому непатченному API. Runtime heartbeat-volume можно оставить неиспользуемым; это не бизнес-данные.
