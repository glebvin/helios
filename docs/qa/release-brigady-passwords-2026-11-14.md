## Исправления при приёмке

В авторском интерфейсе потеря ответа после успешного POST создания бригады воспроизведённо создавала дубль при повторе: менялся requestId. Теперь неизменённая команда сохраняет идентификатор в рамках пользователя/объекта и вкладки, в том числе после перезагрузки. Подтверждение сервера удаляет попытку; изменение команды получает новую идентичность. Пока запись выполняется, повторное нажатие не отправляет вторую команду.

Данные другого объекта скрываются сразу при переключении. Поздний ответ старого объекта не показывает успех и не очищает новый черновик. Списки бригад, назначений и людей читаются по всем страницам. Имена истории берутся из каталога людей организации: отзыв назначения не превращает историческое имя в «Имя не пришло». Это найдено при визуальной проверке и проверяется после перезагрузки. Строка участника переносится на узком экране. Фокус окна запускает перечитывание; конфликт версии не повторяется автоматически.

Релиз содержит реальное изменение API: усиление паролей и multer 2.5.0. Это не frontend-only выкладка. В лимите API384MiB одновременно считается один scrypt; локально по умолчанию два, допустимы только1–2. Старые пароли принимаются; после успешного входа прежний хеш обновляется, пароль не меняется. Приглашения создают новый формат. Ошибочный вход аккаунт не удаляет.

## Релиз и откат

Перед активацией обязательны все4 CI gates текущего кандидата, затем CI точного main, проверка равенства деревьев, свежий резерв БД/файлов с фактическим восстановлением в отдельное место, проверка образа и ограничений памяти. После активации проверяются13 входов, публичный marker/health, сохранность бизнес-данных и файлов; результаты сохраняются в Release.

Обычный старый API не читает новые хеши. Поэтому откат не должен просто включать старый образ или восстанавливать БД. `deploy/helios-staging/compatible-rollback.py` собирает прежние бизнес-код/интерфейс с сохранёнными новым auth/password/invitations, исправленным runtime lock и Compose. Скрипт требует одинаковый SQL, новые неизменяемые выходные файлы, отсутствие.env/node_modules; фиксирует SHA256 заменённых файлов и commit патча. Вариант отката отдельно проверен реальным входом. Данные, новые аккаунты и загруженные файлы при откате не удаляются.
