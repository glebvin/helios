# Смена без нового сбора геолокации — №98

Основание: ТЗ v1.0 §3 п.14 и §16; [Issue98](https://github.com/glebvin/helios/issues/98). Точная версия и результаты CI — в связанном PR/Release. Это ограниченный переход нового веб-клиента, а не закрытие всей R43.

## Изменение

Удалён вызов браузерной геолокации из общего ShiftDialog для работника/мастера, сообщение о неудачном получении позиции и geo из конструктора новых событий. Начало и конец смены сохраняют время, права, причину записи за работника, requestId, версию и зависимость. Даже старое по форме значение на входе конструктора не добавляет координаты в новую команду. Компоновка, CSS, API/SQL и формат существующих очередей не меняются.

## Совместимость и остаток

Старые sessionStorage/IndexedDB-команды могут уже содержать координаты и быть приняты сервером при потерянном ответе. Их payload/hash/requestId и подтверждённая история не переписываются и не удаляются. Сервер сохраняет совместимость старого протокола, в том числе повтор с исходным geo: это проверено отдельно от новых UI-команд.

Поэтому старый клиент или прямой API-клиент ещё может передать geo. Полное прекращение legacy-передачи/приёма и политика уже записанных данных требуют отдельного переходного контракта в R43/#49 до реальных данных. Нельзя молча вырезать поле из подписанной очереди, объявить потерю ответа новой командой или удалить историю. Текущая работа не включает такую миграцию.

## Проверки

-77 frontend unit-тестов, TypeScript всех4проектов и production build прошли. Постоянные тесты конструктора исключают координаты в start/end при старом-shaped входе; policy-check запрещает browser collection API в исходниках приложения. Они выполняются в project-checks.
-Расширен `qa/r26-day.mjs`: явный `HELIOS_PRIVACY_REVIEW=1`, разрешён только свой loopback PostgreSQL54447/API4383/web5240 и проверяется data_directory. Остальные режимы/предохранители сохранены.
-Браузерная проверка подставляет доступную позицию и считает любое обращение к navigator.geolocation. Ожидается0; перехваченные новые shift_start/end не содержат geo. Проверены потерянный ответ после серверной записи, повтор той же команды, offline→online и один результат без дубля.
-Соседние сценарии: интервал работы/жест завершения, объём с запятой, файл с теми же байтами после reload, второй закрытый интервал, два окна утверждения/409, Excel и серверные403дляПТО/работника. Legacy-shaped start/end повторяются как duplicate с сохранённым исходным payload.
-Полные результаты Chromium/WebKit и текущий CI фиксируются в PR. Сценарий браузера выполняется локально на собственной QA; наличие qa-файла не означает, что он запускается в CI. Физические телефоны не проверялись;390px — viewport, не устройство. CSS/общие визуальные компоненты не менялись, экран390px осмотрен.

Команда на подготовленном собственном контуре:

```sh
TSX_TSCONFIG_PATH=apps/api/tsconfig.json HELIOS_PRIVACY_REVIEW=1 \
HELIOS_R26_API=http://127.0.0.1:4383 HELIOS_R26_WEB=http://127.0.0.1:5240 \
HELIOS_R26_ADMIN_DATABASE_URL=postgres://helios:helios@127.0.0.1:54447/helios \
HELIOS_R26_BROWSER=chromium node --import ./apps/api/node_modules/tsx/dist/loader.mjs qa/r26-day.mjs
```

Пароли выше относятся только к новому loopback-кластеру скрипта db.mjs. Для WebKit меняется HELIOS_R26_BROWSER. Общий стенд/контуры Cursor не используются. Перед запуском API применяются миграции только в этом QA, собирается frontend и запускается его preview. Подробности — DEVELOPMENT; seed/reset активного стенда запрещены.
