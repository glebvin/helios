## Исправления по результатам проверки

- Реально воспроизведён дубль: сервер принял POST, ответ потерян, повтор после reload создал две карточки. Номер неподтверждённой команды создания теперь сохраняется в sessionStorage отдельно для пользователя/компании. То же тело после reload повторяет тот же requestId; после подтверждения запись попытки удаляется. Это метаданные повтора, не подмена серверного списка.
- Фоновые чтения не стирают введённый черновик и не поднимают его expectedVersion молча. Временный отказ чтения сохраняет форму с видимым предупреждением; отказ доступа/404 скрывает недоступные данные.
- Устаревшая версия получает явный конфликт; отдельное чтение карточки загружает новую основу для осознанного повтора.
- При нескольких организациях нужен выбор; неизвестная организация существующей карточки не заменяется первой.
- Общий 409 больше не описывается как успешно сохранённый повтор: конфликт телефона и несовпадение команды различаются.
- Одновременные submit блокируются синхронно; поля недоступны во время записи. Запись доступна только director, подтверждение показывается после ответа API.
