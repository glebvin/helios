# Карточка сотрудника — визуальная доработка «Документов»

Основание [R07/PR60](https://github.com/glebvin/helios/pull/60), `c36d69c858903c10681046f47fd03d497ce53ee8`. Ветка `codex/dokumenty-sotrudnika-design`, отдельное визуальное изменение поверх пакета R04–R07. Владелец подтвердил работоспособность локального сценария и прямо попросил исправить дрожание, поставить квалификации/доступ рядом и свернуть попытки в строки. Это не разрешение merge/deploy. Main/сервер21b4bde и остальные PR не изменены.

## Изменение

- Сверху равные колонки: квалификации слева, доступ/назначение справа. На узком окне до1000px — одна колонка. Кнопки открытия доступа и назначения акцентные, рядом со своими состояниями. Пояснения сокращены, подробность про различие доступа/назначения доступна отдельно. Существующая палитра и навигация сохранены.
- Ниже история попыток: одна строка с номером, датой и статусом справа. Вся строка — нативный summary/details, работает мышью и клавиатурой. Разворачиваются ответы, критичные пункты, причины, предупреждения, версия/снимок шаблона, требования и зафиксированные квалификации. Успешная попытка остаётся историческим результатом; старый шаблон явно помечен. Фоновое чтение не сворачивает раскрытую строку.
- «Новая проверка» находится в заголовке истории. Форма, обязательные ответы и серверные отказы сохраняют прежнее поведение.
- Файлы остаются внизу. Выбор и drag-and-drop работают как прежде: локальное содержимое страницы, без заявления о серверной загрузке.

Причина дрожания подтверждена измерением до изменения: QualificationsPanel на focus/60s удалял page, затем восстанавливал список. Access/Admission вставляли строки загрузки, Admission также временно скрывал строку шаблона/пустой истории. На замедленных350ms GET квалификации меняли высоту на122px, следующие блоки смещались на122px, Access дополнительно менял высоту на26px. Теперь уже прочитанные данные сохраняются до ответа; индикатор первичной загрузки не вставляется в заполненный блок при фоновом запросе. Ошибки/отказ доступа по-прежнему скрывают неподтверждённые/недоступные данные. На тех же данных измеренные изменения координат и высот всех трёх панелей —0px.

API-команды, версии/идемпотентность, роли, SQL, backend, зависимости и данные ручной проверки владельца не изменены. Прежние папки Cursor не затронуты.

## Дизайн и проверки

Запрошенный навык KME не найден среди установленных Codex/Agents/Cursor навыков, включая поиск по имени и содержимому. Применён найденный `/Users/Gleb/.cursor/skills/ui-ux-pro-max/SKILL.md`: целевая рекомендация UX Layout/Content Jumping — стабильные контейнеры асинхронных данных, адаптивность и проверка контраста/клавиатуры. Запросы React-справочника по accordion/keyboard не дали проверенного совпадения; нативный details/summary выбран по общему HTML-поведению, не приписывается базе навыка. Karpathy-guidelines — ограниченная правка, без соседнего рефакторинга. Taste-skill прочитан, но его маркетинговые правила не применяются к этой продуктовой странице.

- TypeScript всех пакетов, production build, docs и28 прежних frontend unit tests — успешно. Предупреждение о размере JS bundle сохраняется; оптимизация вне этой задачи.
- `qa/people-documents-browser.mjs`:9 браузерных сценариев — две равные колонки/порядок; стабильные координаты при замедленном focus-refresh; раскрытие Enter/сворачивание мышью и полные ответы; сохранение раскрытия после обновления; светлая/тёмная темы;390px без горизонтального overflow; выбор файла; drag-and-drop; файлы после истории.
- Повторены17 сценариев квалификаций R04,17 допуска R06 и15 доступа/назначений R07 — **всего58** браузерных сценариев. Отрицательные роли, потерянный ответ/reload, stale version, сохранение черновика и серверное подтверждение сохранились. R06 проверки адаптированы к намеренно скрытым подробностям: сначала раскрывают строку, затем проверяют причины. Новая summary-подпись «Пройдена» не подменяет подробное «Пройдена на момент записи».
