# R30.1 — первое решение мастера по объёму

Основание: main d21b7dfc998ca5521d5b3892e602d5099ac0fd54, задача #36, ТЗ v1.0 §6.1/§9–11 и T-06, D-03. Реализован один ограниченный результат: из предъявленных18 мастер подтверждает17, разница1 хранится с причиной и устойчивой идентичностью принятой части. Это реализация и проверки автора Codex, не независимая приёмка и не завершение всего R30.

## Контракт

- GET `/api/v1/projects/{project}/volume-reviews?day=YYYY-MM-DD&limit=25&offset=0`: сообщения управляемого исполнения за гражданский день компании, решение мастера и текущий самоконтроль; итоги по всем доступным строкам дня отдельно по единицам, независимо от страницы. Непроверенное количество — null, записанный ноль —0.
- GET/POST `/api/v1/projects/{project}/volume-reviews/{report}`: карточка/первое решение. POST содержит requestId, expectedVersion, checklistRunId, acceptedQuantity, reason. Последний самоконтроль задания должен быть успешен; его неизменная запись закрепляется в решении. Старый успешный результат нельзя выбрать поверх позднего критичного отказа.
- Пишет только действующий мастер назначенного объекта; РП/ПТО читают, рабочий читает только свои факты с активным назначением. Чужая компания, объект или работник не раскрываются. Права перечитываются после ожидания блокировок и перед replay. Работодатель факта определяется сервером через исходное задание/сотрудника, не клиентом.
-0 ≤ принято ≤ предъявлено, точность3знака, при разнице нужна причина. Решение версии1 неизменно и содержит отдельный UUID принятой части при положительном количестве. Исходный факт не переписывается. Повтор requestId возвращает прежний результат; другое тело с ним409. Два мастера дают201/409 и одну принятую часть. Новое изменение закрытого решения отвергается409; корректировки требуют отдельного следующего результата.
- Прежний `/execution/reports` сохраняет provisional=true/acceptedQuantity=null: это сообщение рабочего, не подтверждение ПТО. Итоги первого этапа показаны в новом разделе, общая сводка R38 не объявляется завершённой.

## Интерфейс

«Приёмка» → «Самоконтроль мастера» → «Открыть» → количество и причина → «Подтвердить объём». Прежние факты, файлы, табель и локальные демонстрационные вкладки сохранены. РП и ПТО читают решение без кнопки подтверждения. День предъявления можно выбрать отдельно, в том числе за прошлый период. Служебное объяснение ступеней под i. На390px строки нового списка становятся карточками с доступной кнопкой44px; прежняя компоновка остальных экранов не меняется.

При потерянном ответе команда с исходными ответами, версией и requestId остаётся в sessionStorage/памяти текущего пользователя. После reload открыть предъявление и повторить исходное решение. Пока исход неизвестен, форма не подменяет команду.409 не приводит к автоматической смене версии. Это повтор онлайн-команды мастера, не новая автономная офлайн-очередь.
