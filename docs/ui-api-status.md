## Пакет 1

Шапка берёт объекты из `GET /api/v1/projects`. Один доступный объект выбирается сам. Дата — гражданский день и пояс из `GET /api/v1/overview`, не часы компьютера. Последний разрешённый объект и день лежат в `localStorage` только как предпочтение. Смена объекта отбрасывает устаревший ответ.

Реестр, карточка, квалификация, чек-лист, назначение и бригада идут через v1. Организация для новой карточки по-прежнему берётся из `GET /api/desk`: справочника организаций в v1 нет. Скан не загружается, сохраняется текст `documentReference`. Требования вида работ к материалам и ИД в форме не выключаются.

Команды записи людей, допуска, назначений, бригад и справочников видны только директору. Прораб приглашает работника, когда у него есть объект.

Проверено 10 ноября 2026 на локальном API `127.0.0.1:4343`, два окна Vite:

- Директор создал карточку, квалификацию, зону, вид работ, шаблон допуска, прошедший чек, назначение и бригаду.
- Второе окно директора после обновления страницы увидело ту же карточку, назначение и бригаду.
- Окно прораба не показало команд директора. У учебного прораба нет членства v1 в объекте, поэтому список объектов пуст. Это данные seed, не скрытый объект.

`tsc --noEmit` для `@helios/web` после пакета 1 — без ошибок.

## Пакет 2

Обычная форма задания пишет и читает только v1. `POST /api/tasks` эта форма не вызывает. Список — выбранный объект и гражданский день шапки. Карточка остаётся справа. Степпер показывает план: черновик, согласование, опубликовано. Перетаскивания нет, смена и приёмка качества с этого списка не запускаются.

Доступ к объекту — отдельная панель `GET/PUT /projects/:p/memberships`. Она не меняет допуск и производственное назначение. После нового прошедшего чека кнопка «Назначить» берёт этот чек, даже если строка назначения ещё показывала старый запрет.

Проверено 10–11 ноября 2026 на локальном API `127.0.0.1:4343`. День кабинета в сценарии — `2026-11-11`. Учебные данные не очищались, `db:seed` не запускался.

- Прораб с доступом сохранил черновик «Уборка секции», записал чек-лист фронта и отправил на согласование.
- Руководитель в другом окне увидел задание и сначала не смог опубликовать: у исполнителя не было чек-листа допуска. После квалификации, проверки и назначения публикация прошла. Обновление страницы оставило задание.
- Руководитель вернул задание с причиной. Прораб увидел черновик и отправил снова.
- Правка названия у руководителя сделала чек-лист фронта недействительным. Публикация остановилась с текстом «Сервер не публикует: готовность не пройдена». Новый чек-лист снял запрет.
- Одновременное сохранение показало «Вы отправили версию 4. На сервере уже версия 5». Чужое название не заменилось. Повтор того же `requestId` вернул тот же идентификатор, второй строки не появилось.
- Иван увидел опубликованное задание на вкладке «Задание» и после обновления страницы. Зарегистрированный по приглашению Олег это задание не видит: прямой `GET` отвечает 404 `not_found`.
- Прямой `POST .../publish` с актуальной версией от прораба и от рабочего — 403 `role_denied`. Прямой `POST /api/tasks` — 410 `task_creation_retired`. Прораб не меняет доступ: `PUT .../memberships` — 403.
- Отдельный вид «Уборка» создан без требований. Вид «Облицовка» не переключался. Задание «Облицовка секции» со ссылкой на лист осталось на согласовании: сервер закрывает публикацию из-за материалов, приёмки предшественника и исполнительной документации.

`tsc --noEmit` и `vite build` для `@helios/web` после пакета 2 — без ошибок. Сборка по-прежнему предупреждает, что основной JS больше 500 кБ.
