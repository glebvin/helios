## Что проверено

1. TypeScript API/domain/worker и frontend; production-сборка Vite. Предупреждение о JS chunk примерно 669 КБ остаётся, это не ошибка сборки.
2. Новый Linux runtime, 125 production-зависимостей по отдельному lockfile; в контейнере исполняется скомпилированный JS с decorator metadata. SQL и OpenAPI доступны по ожидаемым относительным путям.
3. Свежая PostgreSQL: все 10 миграций применены; повторный прогон не меняет схему повторно. API использует ограниченную роль, не владельца БД.
4. Учебная серверная цепочка: сотрудник/допуск/назначение → задание/фронт/публикация → смена/работа/окончание → объём `1.250` → утверждение часов → Excel. Успешный smoke зафиксировал 36 проверенных API-ответов плюс проверки байтов/результатов.
5. Точный повтор события вернул duplicate, один итоговый отчёт сохранился. Проверялся серверный протокол; это не сертификация всех повторов текущего UI.
6. Рабочий не может утвердить собственные часы — 403. Чужая недоступная запись скрывается — 404.
7. Приватный PNG: reserve/upload/attach/download, повтор PUT, совпадение SHA-256. Без авторизации скачивание запрещено.
8. XLSX размером 4967 байт: ZIP проверен, workbook и worksheet XML разобраны. Это настоящий Excel, не переименованный CSV.
9. Публичные HTTPS-проверки: страница/health — 200; `/.env` — 404; три учётки проходят login/me/legacy desk; logout отзывает сессию; стандартный dev-пароль отклоняется.
10. В Safari открыт и прочитан реальный экран входа с пометкой тестового стенда. Полный сквозной сценарий текущего UI на физических телефонах ещё не проверен.
11. После обновлений и перезапуска данные и файлы сохранены. Снята копия БД и файлов, БД восстановлена в отдельную временную базу: совпали counts users/reports/files/approvals (6/2/2/2), восстановленный файл совпал по SHA-256. Временная база удалена после проверки.
12. Mini App `app.evegunina.ru/api/health` продолжает отвечать 200.

В ходе запуска исправлены два инфраструктурных дефекта: capability официального бинарника Caddy при `cap_drop: ALL` и порядок скрытых путей перед SPA fallback. Добавлен HTTP healthcheck gateway. Проверочные сценарии уточнены по фактическим HTTP-статусам контракта; бизнес-ограничения сервера не ослаблялись.

## Вход и первый тест

Логины: `director@pilot.helios`, `master@pilot.helios`, `worker@pilot.helios`. Пароли случайные и уникальные; в репозиторий не включены. На сервере они хранятся в `/opt/helios-staging/credentials.json`, mode 0600. По отдельному разрешению владельца сохранён закрытый локальный файл с инструкцией доступа на его Mac.

1. Руководитель: «Сегодня» → «Рабочий день» → «Подготовить день».
2. Выйти и войти работником: «Начать смену» → «В работу» → «Закончить смену» → «Сдать объём».
3. Выйти и войти руководителем: «Утвердить часы» → «Скачать Excel».

Для контрольных испытаний созданы отдельные сотрудники с префиксом `Я QA`, чтобы основной Иван оставался свободен для первого пользовательского сценария. Они содержат только вымышленные данные.

## Команды состояния

Вход с этого Mac: `ssh progress-interface`; при проблемном VPN-маршруте ранее проверен `ssh -B en0 progress-interface`.

На VPS:

```bash
cd /opt/helios-staging/current
docker compose --project-name helios-staging --env-file /opt/helios-staging/.env -f compose.yaml ps
docker compose --project-name helios-staging --env-file /opt/helios-staging/.env -f compose.yaml logs --tail 50 api worker gateway
```

Не выводить полный Compose с подставленными секретами в публичные отчёты. Проверка синтаксиса — `config --quiet`.
