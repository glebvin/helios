# Как читать готовность HELIOS

- `GET /api/health`:200 означает, что HTTP-процесс отвечает. Его нельзя считать подтверждением БД или worker.
- `GET /api/ready`:200 означает успешную последнюю пробу,503 — перечисленные в checks отказы. Ответ не содержит адресов БД, паролей или персональных данных; Cache-Control:no-store. Наблюдение кэшируется внутри процесса до5с; отдельная попытка ограничена2с.

`db:down`: проверить доступность PostgreSQL и сеть. `queue:down`: проверить доступ к фиксированной очереди pg-boss; это не размер backlog и не доказательство выполнения задания. `evidence:missing/full/unwritable`: каталог отсутствует, свободно менее64MiB или нет права записи. Не удалять файлы ради зелёного сигнала. `worker:stale`: нет обычного файла heartbeat, дата некорректна либо возраст более30с. Сначала проверить состояние/логи worker и общий volume. В production not_configured для worker тоже вызывает503. `backup:not_configured` не блокирует готовность: внешнее резервирование и его наблюдение ещё не подключены, R46 остаётся открытой.

На стенде Docker Compose задаёт обоим процессам `/var/run/helios/worker.heartbeat`. Worker записывает отметку каждые10с после проверки БД/очереди; API читает общий volume readonly. Docker health worker показывает эту свежесть. Docker не перезапускает контейнер автоматически только из-за статуса unhealthy. API healthcheck по-прежнему проверяет liveness, чтобы отказ БД не вызывал цикл перезапусков.

В логах API при изменении отказа появляется `ready db,queue,worker` с соответствующими именами; после восстановления — `ready recovered`. Worker пишет `worker_heartbeat` и восстановление без текста исключения. Сам запрос readiness не отправляет уведомление владельцу. Постоянный внешний наблюдатель/адресат не настроены этим изменением.

Оператор проверяет HTTPS readiness и Docker состояния/логи. Нельзя выводить `docker compose config` без `--quiet` или окружение контейнера в публичный журнал: там могут быть секреты. Не перезапускать БД и не выполнять seed/reset для восстановления readiness. Для воспроизведения отказов использовать `qa/ready-integration.mjs` на одноразовом контуре.

При неудачном выпуске вернуть предыдущие application image/Compose/current, сохраняя постоянные БД и evidence. Для выпуска R47 предыдущий9c74a4d совместим с v2-паролями. Резерв восстанавливается в отдельное место для проверки; откат приложения не восстанавливает бизнес-БД. [Отчёт приёмки](../qa/readiness-r47-2026-11-14.md).
