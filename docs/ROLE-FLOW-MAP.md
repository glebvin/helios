# Карта основных ролей и разрывов

Дата: 11 ноября 2026. Основа: размещённый восстановленный frontend из runtime 1658687e1422, исходники a68c6f1. Это карта планирования, не утверждение полной работоспособности.

## Выбранные роли

| Роль | Продуктовая задача | Текущее серверное право | Следующие карточки |
| --- | --- | --- | --- |
| rp / director | Подготовить людей, опубликовать задания, проверить часы | Реальные действия руководителя по контракту | R01–R12, R18–R21 |
| master | Вести назначенные работы и видеть факты | Чтение назначенного объекта; ограниченные команды заданий; нет утверждения часов/допуска | R02, R07–R12, R18–R21 |
| worker | Выполнить свою смену и сообщить объём/фото | Свой сотрудник, действующее назначение, свои опубликованные задания | R13–R17, R23–R26 |
| pto | Проверять факты, файлы и табель | Назначенный объект; чтение/экспорт по контракту, без записи утверждения часов | R18, R20, R22 |

Роль в шапке не определяет API-доступ. Проверки живут на сервере. Девять дополнительных кабинетов ограничены чтением прежнего desk; их отображение не разрешает выдавать им director/pto для доступа к v1.

## Первичные источники

- apps/web/src/api.ts — старые createTask/desk/sync/accept.
- apps/web/src/dayflow.tsx — учебная подготовка, фиксированные сущности/параметры.
- apps/web/src/book.tsx и outbox.ts — локальные данные прежнего интерфейса.
- apps/api/src/workforce.service.ts — retired create и граница legacy/managed.
- apps/api/src/*controller.ts, *service.ts и apps/api/openapi.json — фактические запросы и права.
- packages/offline — существующий модуль доставки.
- docs/clean-staging-2026-11-11.md — предыдущая проверенная выкладка.

Документы ui-api-coverage/status и отчёты пакетов 1–4 относятся к предыдущим компонентам. Их отдельные методы можно изучать как пример, но целый экран не переносить обратно вместе с нежелательным оформлением.

## Граница настоящей проверки

Нынешний проход по браузеру проверяет вход, доступные экраны, пустые состояния и формы без создания рабочих данных. Полный рабочий день новой интеграции ещё не пройден и здесь не объявляется. Фактические наблюдения перечислены в [отчёте](qa/repository-setup-2026-11-11.md).
