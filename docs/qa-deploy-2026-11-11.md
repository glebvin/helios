## Локальный сценарий в обычном интерфейсе

Отдельные данные, без seed. День кабинета `2026-11-11`, пояс `Europe/Moscow`.

Приглашение руководителя создало работника «Я QA Смена». После регистрации объект был доступен, производственного назначения ещё не было. Руководитель записал квалификацию, пройденный допуск и назначение. Прораб создал «Уборка QA секции»: план 4,75 м2, 14:10–17:40, исполнитель новый работник. Чек-лист фронта записан, задание ушло на согласование, руководитель опубликовал его. После обновления страницы название, исполнитель и план совпали в обоих окнах.

Работник начал смену. Точка не определилась за отведённое время, координаты объекта вместо неё не подставились. Дальше: работа по этому заданию, перерыв, возврат к работе, простой «Оборудование» с комментарием. Смена закрыта кнопкой «Завершить смену» прямо из простоя. Сообщено 3,2 м2. После обновления страницы смена закрыта, объём и история на месте.

Два окна прораба одновременно правили другой черновик. Второе сохранило «Конфликт QA окно Б». Первое получило: «Вы отправили версию 1. На сервере уже версия 2: «Конфликт QA окно Б». Запись другого человека не заменена.» Название второго окна осталось.

Фото результата один раз не ушло на сервер, событие смены и объём при этом получили «Передано на сервер». В отправке было: «Отметка передана. Фото отправляется.» Повтор передал тот же файл и не создал второе событие выполнения.

Работник не прочитал день другого сотрудника: 404. Утверждение своих часов — 403. Excel — 403. Свой день читается. У прораба на табеле нет кнопок утверждения и отмены. Excel руководителя — настоящая книга: присутствие «Я QA Смена» 144647 мс, работа 34255, перерыв 11047, простой 79918. Подтверждённые итоги равны источнику, версия 1, причина сверки на месте.

Живая «Приёмка» больше не показывает очередь и кнопку «Принять». Текст: решение ПТО и строительного контроля не записывается. «Материалы» подписаны как черновик браузера без входного контроля. «Акты» прямо говорят, что подпись и передача не реализованы. Это не приёмка качества: пакеты 3–4 её не делали.

`tsc --noEmit` для web и API — без ошибок. `vite build` — успех, прежнее предупреждение о JS больше 500 кБ. Отдельных тестов web нет. API не менялся, набор time-api заново не гонялся. Основной сценарий в WebKit не повторялся: двоичный WebKit Playwright на машине есть, запускателя в этом репозитории нет, новый пакет не ставился.

## Как начать

1. Открыть https://helios-test.evegunina.ru/ и войти прежним аккаунтом руководителя. Пароль остаётся тем, что уже выдан на сервере; здесь он не повторяется.
2. На «Сегодня» и в «Табеле» видны прежние дни и новый день «Я QA Стенд» за 11 ноября.
3. «Приёмка» должна сказать, что решение ещё не подключено. Кнопки принятия там нет.
4. Новый работник: «Люди» → приглашение → регистрация в другом окне → квалификация, допуск и назначение → задание прораба → публикация → смена на телефоне.
