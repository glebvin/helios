# Смена работника — R13–R17

Технические проверки выполняет агент. Здесь владелец оценивает понятность и удобство на тестовом стенде. Не очищайте базу: создайте отдельного учебного сотрудника/задание при необходимости.

1. Руководитель: у сотрудника есть действующий допуск, доступ и назначение. Есть опубликованное задание с этим исполнителем и пройденной готовностью фронта.
2. Работник: «Моя смена» показывает его объект, день и своё задание; единица/объём совпадают с заданием руководителя. Чужих заданий и кнопки создания нет.
3. Начните смену и проверьте подтверждённое состояние. Отмена формы ничего не записывает. Без сети запись недоступна и успех не появляется.
4. «В работу» → «Перерыв» → «Продолжить» → «Простой» с причиной → «Продолжить». Состояние соответствует действию; задание не переезжает в другую колонку от перерыва.
5. Короткий свайп завершения не заканчивает смену. Полный свайп срабатывает после отпускания. После подтверждения смена закрыта.
6. Сдайте положительный объём с запятой. Ноль не принимается. После нового входа виден тот же объём и пометка «Не принято»; руководитель видит ту же величину. Это ещё не приёмка качества.
7. Добавьте JPEG/PNG/PDF до8МБ. Видны стадии резерва, байтов и привязки. Сохранённым файл называется только после подтверждения привязки; повтор не создаёт дубль. Новый вход открывает тот же файл.
8. Прораб может записать смену за сотрудника только с причиной; запись отчёта/файла ему не предлагается.
9. На телефоне ширина стабильна, подсказки/диалоги не выходят за экран, список и карточка задания одинаковой ширины. Проверьте профиль и соседнюю карточку сотрудника.

Если закрытых смен за день несколько, этот интерфейс пока не выбирает одну для объёма. Физический телефон и UI-offline требуют отдельной проверки.
