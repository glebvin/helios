# Тест-кейсы кабинета

Документы для проверки компанией. Один файл — один раздел, внутри него несколько связанных шагов. Это не отчёт о уже пройденной проверке и не инструкция для разработчика.

Доступные сценарии по разделам (версию конкретного preview сверять с отчётом агента):

| Раздел | Шаги | Документ |
| --- | --- | --- |
| Кабинет | R01–R03 | [Вход, объект, список и карточка](kabinet.md) |
| Люди | R04–R07 | [Квалификация, допуск и назначение](lyudi.md) |
| Задания | R08–R12 | [Зоны, доска, черновик, фронт и публикация](zadaniya.md) |
| Смена | R13–R17 | [Смена, интервалы, объём и фото](smena.md) |
| Табель | R18–R20 | [Чтение, утверждение, отзыв и Excel](tabel.md) |
| Обзор и ПТО | R21–R22 | [Главная, дела, факты и файлы](obzor-pto.md) |

R13–R17 и пакет R18–R20 имеют отдельные технические отчёты в `docs/qa`; публикацию сверять в GitHub Releases и `/release.json`. Сводка и чтение фактов ПТО проверены в R21–R22; это не полная приёмка качества или актов. Разделы «Сегодня», «Мои дела», «Приёмка», «Материалы» и «Акты» не считать полностью готовыми.

## Где открывать

Адрес актуального preview и подготовленные данные предоставляет агент для конкретного пакета. Старые5207/5208 могут показывать прежние сборки; наличие новой main их не обновляет автоматически. Тестовый сервер — https://helios-test.evegunina.ru/; точная версия указана в `/release.json`.

В шапке выберите **«Учебная площадка»** и нужный день. Второй объект нужен только для проверки, что данные площадок не смешиваются.

Логины и пароль тестовых входов лежат в приватном файле «Доступ и начало проверки.md» в папке `.data/people-review`. В эти документы пароль не входит. Для двух ролей сразу используйте два профиля браузера: вкладки одного профиля делят вход.

## Как отмечать результат

Для каждого кейса достаточно: прошло или нет. Если нет, напишите роль, объект, действие, что ожидали и что увидели. Снимок экрана полезен. Пароли и адреса почты на снимок не берите.

Серая кнопка и серая строка под формой — это незаполненное поле, а не поломка роли. Красный текст — ответ сервера: действие не записалось.
